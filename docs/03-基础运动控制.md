# 03 基础运动控制

> 对应时间：第三周（购买材料、编写代码、调参数）
> 主控：STM32F103C8T6（普中核心板，72MHz）· 驱动：DRV8833 ×2 · 遥控：PS2 2.4G

## 主控选型（STM32F103C8T6 vs ESP32）

### 为什么选 STM32F103C8T6

**结论：F103 够用、够熟、成本低。**

需求盘点：

| 需求 | 资源 |
|---|---|
| 4 路马达调速 | 4 个独立 PWM 通道（20kHz） |
| 1 路舵机 | 1 个 PWM 通道（50Hz） |
| PS2 手柄 | 4 个 GPIO，软件模拟时序 |
| 4 个马达方向 | 4 个普通 GPIO |

F103C8T6 有 TIM3（4 通道）+ TIM4（4 通道）+ TIM2（4 通道），完全够用还有余。

**没选 ESP32 的理由**：

1. **不需要联网**——遥控用 PS2 手柄（2.4G 接收器），不走 WiFi/蓝牙，ESP32 的核心优势用不上；
2. **电平匹配更麻烦**——ESP32 是纯 3.3V 逻辑，而舵机 5V、DRV8833 的 VM 是 7.4V，外围反而更复杂；
3. **生态熟练度**——队里已有的资料、例程、学长经验都在 STM32 + HAL 上，出问题好查；
4. **成本**——核心板十几块，烧了不心疼（这次确实烧掉一颗驱动模块）。

如果以后要加图传、上位机、多机通信，再考虑 ESP32 或 STM32F4。

## 软件架构（裸机 vs FreeRTOS）

### 为什么没用 FreeRTOS，用裸机主循环

我们评估后**没有使用 FreeRTOS，采用裸机程序**：

```
main()
 ├─ 初始化（时钟 72MHz、GPIO、TIM2/TIM3/TIM4）
 ├─ while(1)  主循环，周期 10ms
 │    ├─ PS2_Poll()        读一帧 9 字节（约 0.4~2ms）
 │    ├─ 模式检查           掉模式就停车（安全底线）
 │    ├─ 摇杆 → 速度映射    死区 + 60%~100%
 │    ├─ 麦轮运动学解算     4 个加减法 + 归一化
 │    └─ 写 4 个 CCR + 4 个方向脚
 └─ HAL_Delay(10)
```

**不用 RTOS 的理由**：

1. **任务量小**——全部工作都是微秒级，单循环的实时性完全够；
2. **RAM 只有 20KB**——FreeRTOS 每个任务要独立栈，多开几个任务就紧张；
3. **调试成本**——裸机出问题打断点就能看；RTOS 出问题是调度问题，大一阶段排查不了；
4. **阻塞问题用计数器和状态机解决**——例如舵机不需要"睡 20ms"，只需每 20ms 写一次 CCR。

**关键纪律：主循环关键路径里禁止出现 HAL_Delay**，否则手柄会明显变"肉"。以后加了 OLED 刷屏、串口协议解析、多传感器，任务开始抢时间时再上 RTOS。

## 电机驱动选型（DRV8833）

| 指标 | DRV8833 | 我们的需求 |
|---|---|---|
| 通道数 | 双 H 桥（2 马达/颗） | 4 轮 = 2 颗 |
| VM 范围 | 2.7 ~ 10.8V | 2S 电池 8.4V 满电，有余量 |
| 电流 | 1.5A 连续 / 2A 峰值 | TT 马达空载 0.2A、堵转约 1.5A |
| 逻辑电平 | 3.3V 兼容 | STM32 直连，不用电平转换 |
| 保护 | 过流、过热、欠压 | 保护马达和模块 |

TT 马达（1:48 减速箱）供电 7.4V，**PWM 限幅 90%** 等效约 6.6V——既提速又不超压太多。实测空载约 200 RPM。

**麦轮横移的取舍**：横移效率只有前进的约 70%（辊子 45° 分解，纵向分量抵消），横移会明显更慢。换 1:120 减速比扭矩更大但速度掉，属于取舍。

**堵转**：没做定量堵转测试（无扭矩计/电流钳），但观察到车轮顶住障碍时 DRV8833 会进入过流保护。软件上：① 最大占空比限 90%；② 手柄掉线立刻停车。

## PS2 手柄通信

### 通信方式

**不是 SPI**，是 PS2 自己的 4 线同步串行协议，用 GPIO 软件模拟时序：

| 线 | 方向 |
|---|---|
| `DAT` | 接收器 → 单片机（输入，必须上拉） |
| `CMD` | 单片机 → 接收器（输出） |
| `CS/ATT/SEL` | 单片机 → 接收器（低电平有效） |
| `CLK` | 单片机 → 接收器（输出） |

帧格式（9 字节，LSB 先行）：`RX[1]` = 模式 ID（0x41 数字 / 0x73、0x79 模拟 / 0x0C 2.4G），`RX[2]=0x5A` 校验，`RX[3][4]` 按键，`RX[5..8]` 摇杆（中位约 128）。

**时序要点（踩过的坑）**：必须等 **CLK 拉低之后再读 DAT**，早读晚读都会拿到错位的数据。

### 断联处理（安全底线）

> 手柄关机或掉模式时，接收器**仍然会回 0x41**，摇杆字节全部变成 `0xFF`——程序若照常计算会认为"摇杆推到最底"，**车会自己冲出去**。

所以每轮检查 `RX[1]`：不是模拟模式 ID 就**立刻停车**。**判据不是"读到了预期值"，而是"数据会不会随操作变化"**——我们一开始就被 0x41 骗过。

对频流程：接收器断电重上电 → 按住配对键 2~3 秒 → 手柄开机靠近 → 灯从"闪"变"常亮"。

### 延时表现

一帧约 0.4~2ms，主循环 10ms → 手感延迟约 10~15ms，可接受。

## 麦轮运动学解算

**公式（X 型辊子排布）**：

```
左前 = 前后 - 横移 + 自旋
右前 = 前后 + 横移 - 自旋
左后 = 前后 + 横移 + 自旋
右后 = 前后 - 横移 - 自旋
```

**归一化（关键）**：斜推摇杆时四个轮子的值可能超过 100，直接下发会削顶导致走歪。取四轮绝对值最大值，超过 100 就等比缩放——方向不变、比例不变，只整体降速。

**斜 45° 平移**：左边两轮反转、右边两轮正转，每个轮子推力沿辊子 45° 分解，横向分量叠加推动横移，纵向分量左右抵消。**自旋**：左右两侧反转形成力偶。

**摇杆映射（踩过的坑）**：

```c
if (mag <= 20) return 0;              // 死区
speed = 60 + mag * 40 / 107;          // 映射到 60% ~ 100%
```

**为什么下限是 60% 而不是 0%**：TT 马达有**启动死区电压**，实测 48% 占空比时同一批马达有的能起步、有的起不来，线性映射会让车画歪。

## 电机调试踩坑记录

按"现象 → 定位 → 根因 → 解决"记录真实经历：

1. **电机只有一个方向转**：换通道测试排除马达 → 万用表量方向脚发现反转时读不到 3.3V → 根因是**方向脚被插到 GND 上**。解决：换引脚 + 代码里给每个轮子留 `sign` 参数，方向不对改代码不改接线。
2. **上电某轮自转，换模块没用**：换 DRV8833 现象不变 → 根因是**马达线插到面包板上与电源连通的同一行**，马达成了直连电源。解决：马达线直接插模块排针，不过面包板。
3. **手柄时好时坏、摇杆全 0xFF**：Keil Live Watch 看 `ps2_rx` 发现出问题时 `RX[1]=0x41` → 根因是**手柄自己从模拟模式掉回数字模式**（2.4G 链路抖动/电压不足复位）。解决：每轮检查 ID，不对就停车。
4. **引脚悬空导致乱转**：诊断程序没初始化马达引脚，浮空输入被 DRV8833 读成高电平。解决：**任何程序初始化时都把方向脚拉低、PWM 写 0**。
5. **共地问题**：电池 GND 和板子 GND 没连，PWM 信号没有参考地等于不存在。解决：所有 GND 汇到一条母线。
6. **占空比低只嗡嗡响**：启动死区电压。解决：速度映射改 60%~100%。

**烧过 / 接反过**：烧了一颗 DRV8833（H 桥击穿，某轮只一个方向转，换模块即好）；马达线接反（代码 `sign=-1` 解决）；电源接反（万幸先量了电压）；面包板同行短路。

## 控制参数迭代

| 参数 | 迭代过程 | 最终值 | 为什么 |
|---|---|---|---|
| 死区 DEAD_ZONE | 20 → 6 → 20 | **20** | 6 太敏感手一抖就动；20≈8% 行程手感刚好 |
| 最小驱动量 MIN_DRIVE | 50 → 62 → 60 | **60** | 50 有轮子起不来；62 有点窜 |
| 最大占空比 MOTOR_MAX_PCT | 80 → 100 → 90 | **90** | 80 太慢；100 时正反转变恒定电平不稳 |
| 反向补偿 REV_BOOST | 加过 8 后取消 | **0** | 占空比提到 90 后反向不弱了 |

**为什么必须调**：TT 马达启动死区电压同批能差 0.5V；摇杆中位实测是 128/127 而非精确值；"1 PWM + 1 方向脚"驱动方式正转滑行、反转刹车，天生不对称；7.4V 对 6V 马达超压，速度与发热取舍。

## 电源架构

电池 2S 18650（7.4V 标称 / 8.4V 满电），三个节点 + 一条公共地：

- 7.4V 马达母线 → 两颗 DRV8833 的 VM
- 降压 #1 → 5V 逻辑母线（板子 + PS2 接收器）
- 降压 #2 → 5V 舵机母线（**与逻辑 5V 分开**）

**为什么舵机 5V 要独立**：舵机一动 0.7A（MG996R 2.5A）冲击会拉塌共用电源——表现为"板子莫名复位""手柄掉回数字模式"。分开后逻辑电源干净了。**两路 5V 绝不能并联**（高的往低的灌电流）。

**为什么用端子排不用纯杜邦线**：杜邦线 26~28AWG 载流 0.5~1A，四马达堵转 5~6A 会软化冒烟；端子排螺钉压接扛得住且接触可靠。**面包板只走信号不走功率**（触点约 1A，且一行 5 孔内部连通——我们实际踩过这个坑）。

## 机电协同适配

1. 舵机角度限位（机械行程不到 180°，软件夹在 10°~170° 防顶死烧舵机）；
2. 电机急停（手柄掉线立即停车，硬性安全逻辑）；
3. 速度下限 60% 适配马达启动死区；
4. PWM 限幅 90% 适配 7.4V 超压；
5. 上电舵机先回中位（避免从未知位置猛甩打坏齿轮）。

**舵机控制细节**：TIM2 通道 2，50Hz（PSC=71 → 1MHz，ARR=19999 → 20ms），脉宽 0.5~2.5ms 对应 0°~180°，`CCR = 500 + angle * 2000 / 180`。**PWM 不能停**——舵机保持力来自持续 PWM，停了会因重力掉下来，所以只改 CCR 不停通道。

## 效果验证

- 四轮麦轮全向移动（前进/横移/自旋）稳定；
- 手柄响应约 10~15ms，手感良好；
- 掉线停车保护实测有效。
